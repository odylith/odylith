# Upgrade Recovery for 0.1.11 Installs

Odylith v0.1.12 is a recovery release for the bad 0.1.11 first-run path. It
targets the failures seen in fresh consumer installs: missing first-run shell
surfaces, empty Registry dashboards after component registration, Atlas prompts
that could not land first, polluted `odylith show` suggestions after install,
and Claude Code visibility recovery leaking as Stop-hook errors.

After upgrading an existing 0.1.11 repo, run:

```bash
./.odylith/bin/odylith doctor --repo-root . --repair
```

Doctor repair now fixes the known 0.1.11 drift, removes stale intervention
noise, and attempts the missing first-run dashboard render itself. If it reports
that shell surfaces are still incomplete, follow with:

```bash
./.odylith/bin/odylith sync --repo-root . --proceed-with-overlap
```

- Registry `odylith component register` now emits validator-accepted metadata and
  `doctor --repair` normalizes the 0.1.11 `category: detected` and
  `qualification: detected` records already written in consumer repos. Do not
  hand-edit `odylith/registry/source/component_registry.v1.json` for this
  recovery; upgrade, run doctor repair, then rerun the blocked sync or refresh.
- First install now renders shell surfaces through the same overlap-aware path
  operators were told to use manually, so fresh installs should not stop with
  missing `radar.html`, `atlas.html`, `compass.html`, `registry.html`, or
  `casebook.html`.
- `doctor --repair` now notices missing first-run shell surfaces and runs the
  overlap-aware surface bootstrap directly. The repair command should no longer
  say completed while leaving the browser empty and making the operator discover
  `--proceed-with-overlap` by trial and error.
- Normal lifecycle output is human-first: `install`, `sync`, and dashboard
  refresh write paths show a short summary plus live progress, while internal
  mutation classes, path lists, and the full step graph are reserved for
  `--dry-run` or `--verbose`.
- Atlas scaffold can create a draft source diagram from the Atlas-first prompt;
  Radar, plan, and doc links can be attached later instead of blocking the first
  visible diagram.
- `odylith show` now ignores Odylith-managed install trees when proposing app
  boundaries, so installed repos are not told to govern Odylith's own generated
  dashboard files as if they were application modules.
- Generated Python host hook and launcher files carry a file-level Ruff
  suppression so `ruff check .` in a consumer repo does not fail on Odylith's
  managed integration shims.
- `odylith uninstall` now detaches root guidance, preserves the repo-local
  `odylith/` governed source-truth tree, removes `.odylith/` local runtime
  state, and removes Odylith-owned Claude/Codex hook entries from host project
  settings. Host configuration directories such as `.claude/`, `.codex/`, and
  `.agents/` are left in place because they may contain user config.
- Claude and Codex bash guards now leave the supported
  `./.odylith/bin/odylith uninstall --repo-root .` command alone while blocking
  raw shell or Python removal of Odylith-managed paths with a message that
  points back to uninstall. Agents should not suggest `rm -rf`,
  `shutil.rmtree`, hook bypasses, commit/snapshot preflights, or a second
  confirmation detour for explicit uninstall requests.
- Claude Code PostToolUse edit/Bash checkpoints and Codex post-bash
  checkpoints now stay silent on successful governed refresh and emit only
  compact failure/skipped-refresh status. Claude Code Stop summary logs only;
  Codex Stop summary logs and may replay a pending already-earned live beat,
  but it no longer authors fresh Observation, Proposal, Assist, Risks,
  History, Insight, continuation, or transcript-proof copy from Stop itself.
  That prevents edit receipts, `Stop hook error`, and `Stop says` replay noise
  from dumping Risks, History, Observation, Assist, `B-096`, or `CB-122` into
  consumer transcripts.
- `doctor --repair` also removes stale 0.1.11 Claude intervention noise from
  consumer Compass streams when product-repo IDs such as `B-096` or `CB-122`
  are not present in that repo's local Radar or Casebook truth. Rerun the
  blocked sync or relevant dashboard refresh after repair if generated browser
  payloads still show old timeline entries.
- Visible intervention recovery copy is now scrubbed for control-plane
  instructions, product-theater phrasing, recursive display instructions, and
  product-repo-only IDs before it can ship. Consumer repos no longer see
  Odylith product records such as `B-096` or `CB-122` in chat unless those
  records actually exist in that repo.
- v0.1.12 keeps the runtime model repo-local. It does not add `attach`,
  machine-global store paths, `odylith repos list`, shared runtime
  materialization, hardlink/reflink reuse, or any user-facing shared-store
  behavior. The release only preserves the contract evidence a future
  migration can trust: runtime version, platform, release asset digests,
  feature-pack asset/platform/path/digest metadata, hot-file and tree trust
  receipts, active runtime root, and activation history. A later dedicated
  workstream can use that evidence to seed an immutable content-addressed
  store, smoke-test a repo-local materialization, switch atomically, and keep
  the previous local runtime for rollback.
