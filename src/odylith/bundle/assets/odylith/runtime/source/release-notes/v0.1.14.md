# Product Governed Harness and General-Purpose Benchmark Model

Odylith v0.1.14 turns the benchmark interpretation work into product truth. The
checked-in [Benchmark Formal Model](../../../../docs/benchmarks/BENCHMARK_FORMAL_MODEL.md)
now states the benchmark contract through the same Product Governed Harness Turn
Gate that consumer prompts, host wrappers, tool approvals, proof receipts, and
stop/finalization checks use. Benchmark scenarios measure Odylith's operating
policy; they do not own a private closure path.

The release win is therefore specific and truthful: Odylith improves grounded
decision quality, bounded action, validation honesty, completion-claim control,
and unnecessary model/tool spend when the product gate has sufficient evidence.
The model does not claim arbitrary live-coding superiority without a separate
repair-required benchmark family. It claims product-policy lift over observable
task classes with equivalent evidence, repo state, and host capability.

This release also closes the migration and browser-surface debt needed to ship
that story safely. Historical 0.1.0 through 0.1.13 installs are exercised
through the 0.1.14 migration runner, release migration gate, and lifecycle
simulator. Casebook lifecycle metadata, Atlas render artifacts, generated
governance dashboards, installed bundle mirrors, and public docs now have
release-observed migration coverage.

Benchmark proof and compare are advisory for this exact release because the
maintainer explicitly waived full benchmark runs for v0.1.14. That exception is
tracked in `odylith/runtime/source/release-maintainer-overrides.v1.json` and
bound to Casebook/governance truth. It does not weaken the default release rule:
future releases return to benchmark proof unless they carry their own
version-scoped tracked override.

- `docs/benchmarks/BENCHMARK_FORMAL_MODEL.md` now defines the product Turn Gate
  function, benchmark observation relation, operating-policy utility, measured
  lift, early-exit proof condition, and generalization boundary in visible
  LaTeX.
- `odylith turn-gate decide`, `tool-check`, and `stop-check` are documented as
  product interfaces. Benchmark wrappers may sandbox, time, log, and score, but
  they must not decide closure independently.
- Live benchmark execution now routes closure through Turn Gate receipts, and
  legacy focused closure helpers remain compatibility/report readers rather
  than private scoring authority.
- `odylith release migration-gate --target-version 0.1.14` covers public docs,
  browser-rendered governance surfaces, install-managed assets, Casebook status
  lifecycle, Atlas render-style freshness, and greenfield release/program
  topology.
- Casebook migration preserves `FixedPendingRelease` as an active pre-release
  state, normalizes historical status/type labels into compact controlled
  tokens, and keeps rendered bug details readable across normal, empty,
  fallback, and upgraded-consumer browser states.
- Atlas migration rerenders stale SVG/PNG assets when render-style fingerprints
  drift, so historical installs pick up the v0.1.14 visual grammar without
  hand edits.
- Existing consumer installs still default to advisory host behavior unless the
  host integration can actually enforce prompt, tool, or stop gates. Managed
  harnesses and trusted hooks may opt into enforcement where the host can block
  side effects.
